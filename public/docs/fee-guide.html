1 Zero

Charges no fee for this direction. Use this when a partner is not billed for a specific transaction type.

When to use

  • Partner has no VCA transactions
  • Fee was waived for a direction during negotiation
  • Direction is not applicable to this partner

How to configure

  1. Select Zero — No fee from the Fee Type dropdown
  2. No additional fields needed — click Save
Example: VLPay has no VCA billing.
Set VCA Fee → Zero

2 Flat

Charges the same fixed PHP amount for every transaction, regardless of transaction size.

When to use

  • Partner has a simple per-transaction fee
  • Transaction amount does not affect the fee

How to configure

  1. Select Flat — Fixed ₱X per transaction
  2. Enter the Fee Amount (₱) — e.g. 8 for PHP 8 per transaction
Example: MaxJoy charges PHP 10 per QRPh transaction.
QRPh Fee → Flat → Fee Amount: 10
100 transactions × PHP 10.00 = PHP 1,000.00 total fee

3 % + Floor

Charges a percentage of the transaction amount, but never less than a minimum floor.

fee = max(amount × rate%, floor)

When to use

  • Fee is percentage-based
  • Small transactions need a minimum charge

How to configure

  1. Select % + Floor
  2. Enter Rate (%) — e.g. 0.7 for 0.7%
  3. Enter Floor (₱) — the minimum fee per transaction, e.g. 1
💡 Enter the rate as a percentage number. For 0.7%, type 0.7 — not 0.007. The portal converts it automatically.
Example: Magic Payment charges 0.7% for QRPh, minimum PHP 1.
QRPh Fee → % + Floor → Rate: 0.7 → Floor: 1
PHP 50 transaction: max(50 × 0.7%, 1.00) = max(0.35, 1.00) = PHP 1.00 ← floor applied PHP 500 transaction: max(500 × 0.7%, 1.00) = max(3.50, 1.00) = PHP 3.50 PHP 2,000 transaction: max(2000 × 0.7%, 1.00) = max(14.00, 1.00) = PHP 14.00

4 % + Floor + Cap

Same as % + Floor, but adds a maximum cap — the fee can never exceed a certain amount.

fee = min( max(amount × rate%, floor), cap )

When to use

  • Partner fee has a ceiling for large transactions
  • Protects partners from very high fees on large transfers

How to configure

  1. Select % + Floor + Cap
  2. Enter Rate (%), Floor (₱), and Cap (₱)
Example: HoPay charges 0.5% for QRPh, minimum PHP 1, maximum PHP 5.
QRPh Fee → % + Floor + Cap → Rate: 0.5 → Floor: 1 → Cap: 5
PHP 100: min(max(0.50, 1), 5) = PHP 1.00 ← floor applied PHP 500: min(max(2.50, 1), 5) = PHP 2.50 PHP 2,000: min(max(10.00, 1), 5) = PHP 5.00 ← cap applied

5 Tiered by Amount

Charges a flat fee that depends on the transaction amount. Larger transactions get a different fee than smaller ones.

When to use

  • Partner fee schedule has a table of amount ranges, each with a different flat fee

How to configure

  1. Select Tiered by Amount — flat fee per amount range
  2. Click + Add Tier for each row in the partner's fee schedule
  3. For each tier: enter Up to amount ₱ (leave blank for the last/default tier) and Fee (₱)
💡 Always leave the last tier's amount blank — it becomes the default for everything above the highest threshold.
Example: PHP 5 for transactions up to PHP 300, PHP 10 for anything above.

Tier 1: Amount ≤ 300 → Fee: 5
Tier 2: Amount ≤ (blank) → Fee: 10
PHP 150 → Tier 1 (≤300) → PHP 5.00 PHP 500 → Tier 2 (default) → PHP 10.00

6 Tiered by Amount + Run Count (AIO-style)

The fee depends on both the transaction amount AND the total number of transactions in the billing run. Volume discount kicks in when the monthly count crosses a threshold.

📋 Currently used by: AIO Solutions

7 Tiered Percentage — Incoming only

The percentage rate changes depending on the transaction amount — smaller transactions have a higher rate, larger ones a lower rate. Optional minimum floor per tier.

⚠️ Available on QRPh and VCA only — not on Disburse.

How to configure

  1. Select Tiered Percentage — % per amount range
  2. Click + Add Tier for each rate in the schedule
  3. For each tier: Up to amount ₱ (blank for last), Rate (%), and optional Min Floor ₱
Example: ≤PHP 120: 0.90% / floor PHP 1  |  PHP 121–250: 0.75%  |  PHP 251–500: 0.60%  |  above: 0.50%

8 Tiered by Count — Disburse only

All transactions in a billing run are charged at the same flat rate, determined by the total number of transactions in the run. Higher volume = lower rate for ALL transactions.

⚠️ Available on Disburse only — not on QRPh or VCA.

How to configure

  1. Select Tiered by Count — all txns same rate based on run volume
  2. Click + Add Tier for each count threshold
  3. For each tier: Up to count (blank for last) and Fee per txn (₱)
Example:
<30,000 txns: PHP 9.50/txn  |  30k–99,999: PHP 9.00  |  100k–299,999: PHP 8.00  |  300k–499,999: PHP 7.00  |  500k+: PHP 5.00
Monthly run = 487 transactions: → Rate = PHP 9.50 (count < 30,000) → Total = 487 × PHP 9.50 = PHP 4,626.50 Monthly run = 55,000 transactions: → Rate = PHP 9.00 (count 30,000–99,999) → Total = 55,000 × PHP 9.00 = PHP 495,000.00

9 Fee Rules

Lets you define multiple conditions with different fee types per condition. The billing engine checks each rule top to bottom and uses the first rule that matches.

When to use

  • Partner has conditions that need different fee types (e.g. Rule 1 = flat, Rule 2 = percentage)
  • Partner has many if-else conditions in their contract
  • None of the simpler fee types above fully covers the schedule

How to configure

  1. Select Fee Rules — multiple conditions with + button
  2. Click + Add Rule for each condition
  3. For each rule set: Amount > ₱ (optional lower bound) and Amount ≤ ₱ (optional upper bound)
  4. Choose the fee type and fill in its fields: Zero / Flat / % + Floor / % + Floor + Cap
  5. Always add a default rule last — leave both amount fields blank
⚠️ Rules are evaluated top to bottom. Put specific conditions first and the default (catch-all) last.

Example 1 — Small transactions free, large ones billed

RuleConditionFee
Rule 1Amount ≤ PHP 100Zero — no fee
Rule 2(default)Flat — PHP 5.00

Example 2 — Mixed flat and percentage

RuleConditionFee
Rule 1Amount ≤ PHP 500Flat — PHP 3.00
Rule 2(default — above PHP 500)% + Floor — 0.8%, floor PHP 3
🗑️ To delete a rule, click the ✕ button on the right of the rule block. Rules renumber automatically.

Quick Decision Guide

Not sure which fee type to pick? Follow this:

Is the fee always PHP 0?
→ Zero
Same fixed amount every transaction?
→ Flat
Percentage, with a minimum?
→ % + Floor
Percentage, with a minimum AND maximum?
→ % + Floor + Cap
Different fixed amount per transaction size?
→ Tiered by Amount
Depends on BOTH transaction size AND monthly volume?
→ Tiered by Amount + Run Count
Different percentage per amount range? (QRPh/VCA only)
→ Tiered Percentage
All transactions same rate, set by total monthly count? (Disburse only)
→ Tiered by Count
None of the above, or mixed fee types per condition?
→ Fee Rules
